# 「上次」網頁版 設計規格

日期：2026-10-05
狀態：待使用者確認

## 0. 背景

「上次」是一個個人用的網頁 app（PWA），放在 `cyril1018/last-time`，用 GitHub Pages 架站。實際要記的是「吃藥、換飲水機濾心、換瓦斯、打電話給某人、轉帳給幣托扣款帳戶」這類事，項目數不多，所以功能刻意收得很窄。

本文件是實作的唯一依據。

## 1. 產品概念

「上次」只做一件事：記下你上次做某件事的時間，然後告訴你過了幾天。

它不是待辦清單：沒有目標、沒有連續天數、沒有進度條、沒有推播。唯一的「提醒」是使用者自己填了「大概多久一次」之後，超過時數字變紅。

三個承諾：

1. 不用帳號、沒有伺服器、沒有廣告、不接任何第三方服務。網站只在第一次開啟和更新版本時連網抓程式本身。
2. 所有資料只存在手機瀏覽器裡，使用者隨時可以匯出一個檔案帶走。
3. 記一筆只要一個動作，不換畫面，記錯可以立刻復原。

視覺安靜：淺色底、少量綠色做動作色、到期才出現紅色。最重要的視覺是「過了幾天」那個數字，天數越多字越大越重。

## 2. 目標裝置與限制

- 主要裝置：Android 手機的 Chrome，加到主畫面使用。
- 其他瀏覽器（桌機 Chrome、Firefox、iOS Safari）要能用，但不保證震動、安裝提示等附加功能。
- 完全離線可用：安裝後飛航模式下所有功能正常。
- 資料存在瀏覽器裡。清除網站資料、解除安裝 Chrome 會讓資料消失，所以備份提醒要積極（見 §5）。

## 3. 技術選型

| 項目 | 選擇 | 說明 |
| --- | --- | --- |
| 語言 | TypeScript | 全專案 strict |
| 畫面 | Svelte 5（runes） | 單一頁面，元件拆分 |
| 打包 | Vite | |
| 測試 | Vitest | 覆蓋 §6 計算規則、§8 備份解析、emoji 猜測 |
| 資料庫 | IndexedDB，透過 Dexie 操作 | 兩張表：items、records |
| 設定 | localStorage | 主題、震動、上次備份時間、備份提醒延後到期時間 |
| 離線與安裝 | vite-plugin-pwa（Workbox） | Service Worker 預先快取所有資源；Web App Manifest |
| 路由 | hash 路由（`#/`、`#/item/:id`、`#/settings`） | GitHub Pages 不需額外設定；配合瀏覽器返回鍵 |
| 字型 | Fraunces（可變字型，OFL 授權）隨網站打包；其餘系統字型 | 不連 Google Fonts |
| 部署 | GitHub Actions → GitHub Pages | 推上 `main` 自動測試、打包、發布 |

不引入任何分析、廣告、錯誤回報 SDK。所有依賴皆為 MIT 或 Apache-2.0 授權。

TypeScript 版本：優先用 7.x；若 Svelte 的型別檢查工具（svelte-check）尚不支援，退回 6.x 最後一版。實作計畫階段確認。

### 3.1 資料流

- 啟動時把三張表全部讀進記憶體（Svelte 狀態），畫面直接從記憶體讀。
- 每次新增、修改、刪除：先改記憶體讓畫面立即反應，同時寫入 IndexedDB。寫入失敗時回滾記憶體並顯示錯誤提示。
- 3000 筆紀錄約數百 KB，全部放記憶體沒有效能問題。
- 第一次啟動呼叫 `navigator.storage.persist()`，請瀏覽器把本站資料標為「保留」，降低被自動清除的機會。結果不影響功能。


## 4. 資料模型

所有 id 都是字串；時間一律存 epoch 毫秒（UTC），顯示時轉成裝置時區。

兩個實體：項目（Item）、紀錄（Record）。沒有分類。

### 4.1 項目 Item

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| id | string | 主鍵 |
| name | string | 例如「換瓦斯」 |
| emoji | string | 新增時依名稱猜（§4.3），之後可改 |
| expectDays | number \| null | 大概多久做一次（整數天）；null＝不判斷到期 |
| archived | boolean | 封存後首頁不顯示，紀錄保留 |
| created | number | 建立時間（毫秒） |

### 4.2 紀錄 Record

| 欄位 | 型別 | 說明 |
| --- | --- | --- |
| id | string | 主鍵 |
| itemId | string | 項目 id，項目刪除時連帶刪除 |
| ts | number | 做這件事的時間（毫秒），精確到分鐘 |
| note | string | 備註，可空字串 |

### 4.4 id 格式

13 碼小寫英數字（base36），由時間戳 + 隨機數組成，例如 `muu6aqvrnk6ye`。匯入時 id 是任意字串，不檢查格式。

### 4.5 規則

- 刪項目連同它的紀錄一起刪，刪前要確認。
- 同一個項目同一天可以有多筆紀錄。

## 5. 設定（localStorage）

| 鍵 | 值 | 預設 |
| --- | --- | --- |
| theme | `system` / `light` / `dark` | system |
| vibrate | boolean | true |
| lastBackupAt | 毫秒或 null | null |
| backupSnoozeUntil | 毫秒或 null | null |

備份提醒條顯示條件：紀錄達 5 筆，且（從未備份 或 距上次備份超過 **14 天**），且現在 > backupSnoozeUntil。按「之後」把 backupSnoozeUntil 設為現在 + 7 天。匯出成功後 lastBackupAt 設為現在。

## 6. 計算規則（`calc.ts`，全部有單元測試）

「過了幾天」用日曆日算，不是 24 小時為一天：昨晚 23:00 做的，今天凌晨看就是「1 天」。日曆日以裝置目前時區為準。

| 規則 | 定義 |
| --- | --- |
| 距上次的顯示 | 距現在不到 60 分鐘：「剛剛」；同一個日曆日：「N 小時」；其他：「N 天」（日曆日差） |
| 首頁排序 | 依最後一筆紀錄的時間，最近的在最上面；沒有紀錄的項目排最下面，顯示「尚未記錄」 |
| 數字大小 | 字級 px = min(44, 22 + 6 × log2(天數 + 1))；字重 = min(680, 420 + 天數 × 4)，兩者由 CSS 自訂屬性驅動 Fraunces 可變字型；「剛剛」與「N 小時」固定 18 px、字重 420 |
| 到期 | expectDays 有值且日曆日差 ≥ expectDays 時，數字和單位改成紅色，日期前加「該做了 ·」 |
| 最近 7 天 | 首頁右上角：7 天內（現在往前 7 × 24 小時）有紀錄的未封存項目數 / 未封存的項目總數 |
| 平均間隔 | 同一項目至少 3 筆才算：（最新一筆 − 最早一筆）/（筆數 − 1），單位天；小於 10 天顯示一位小數，否則取整 |
| 空缺天數 | 細節頁相鄰兩筆的日曆日差；差 0 顯示「同一天」 |
| 補其他日期的月曆 | 週一為一週的開始；今天用外框標示；未來日期灰色且不能選 |

## 7. 畫面規格

沒有底部導覽列。首頁右上角一個齒輪進設定；項目細節從首頁點進去。所有「抽屜」都是從底部滑出的面板，點背景或按返回鍵關閉。

### 7.1 首頁 `#/`

- 頂端左邊 app 名稱「上次」，右邊數字「3 / 8」，下面小字「最近 7 天做過」；再右邊齒輪圖示進設定。
- 備份提醒條（§5）顯示在頂端數字下方，有「去備份」（進設定）和「之後」。
- 清單每一列：左邊 emoji 方塊，中間項目名稱，右邊「過了幾天」的大數字加單位，數字下面小字顯示上次的日期和時間（例如「9月20日 14:32」）。到期時數字變紅、日期前加「該做了 ·」。
- 點一列：進細節頁。長按一列（450 ms）：以現在時間記一筆，不換畫面，震動 30 ms（設定可關），該列閃一下綠色。長按時用 `touch-action`、`user-select: none`、攔截 `contextmenu` 避免跳出系統文字選取或選單。
- 記完後底部浮出一條黑色提示：「已記錄 🛏️ 洗床單 14:32」，右邊兩個按鈕「復原」「備註」。8 秒後自動消失；再記一筆時舊的提示立即被取代。復原＝刪掉剛剛那筆；如果項目是這次新增的，連項目一起刪。「備註」＝打開這筆紀錄的編輯抽屜。
- 底部固定一個輸入框「搜尋或新增一件事」：打字即時過濾清單（名稱包含即符合）；輸入的文字（去頭尾空白後）沒有完全相同名稱的項目時，清單最上面出現一列「＋ 新增『xxx』，以現在的時間記下第一筆」，點它或按鍵盤完成鍵就新增並記一筆（emoji 依 §4.3 猜）；有完全相同的項目時按完成鍵＝對那個項目記一筆。新增或記錄後清空輸入框。鍵盤彈出時用 `interactive-widget=resizes-content` 讓輸入框停在鍵盤上方。
- 沒有任何項目時顯示說明文字和範例膠囊（吃藥、換濾心、換瓦斯、打電話給爸媽、剪頭髮、繳帳單），點膠囊把文字填進輸入框並聚焦。
- 清單最下面一行小字「點一下看細節，長按直接記一筆」。
- 畫面回到前景（`visibilitychange`）時重新計算「剛剛／N 小時」；另外每分鐘重算一次。
- 每列有一個只對螢幕閱讀器可見的「記一筆」按鈕，提供長按的無障礙替代。

### 7.2 項目細節 `#/item/:id`

- 頂端：返回鍵、emoji、名稱、右上角鉛筆（開編輯項目抽屜）。名稱下方小字：「大概每 N 天一次」（有設才顯示）、「已封存」（有才顯示）。
- 三個摘要數字：距上次（到期時紅色）、平均間隔（不足 3 筆顯示「記滿 3 次後計算」）、共幾次。
- 時間軸：由新到舊，每筆一個綠點，顯示「2026年9月20日 週日 14:32」，下方備註。相鄰兩筆之間一行小字「空缺 14 天」或「同一天」。點任何一筆打開紀錄編輯抽屜。
- 底部固定兩顆按鈕：「立即記錄」（主色，寬）和「補其他日期」。立即記錄的行為和首頁長按相同，包含復原提示。
- 返回鍵回首頁。項目不存在（例如被刪）時導回首頁。

### 7.3 編輯項目（抽屜）

- 名稱（必填，去頭尾空白後不可為空）、圖示（可輸入任何 emoji；下方 20 個常用 emoji 快選：📌 🛏️ 📞 💊 💧 🔥 💸 🧹 🫧 🚗 🏃 🦷 🩺 🗑️ 🪴 🍜 🧾 🔋 💡 🔧）、大概多久做一次（整數天，留空不判斷；非正整數視為留空）、封存開關。
- 底部：「刪除項目」（紅）和「儲存」。刪除要彈出確認，說明會連同 N 筆紀錄一起刪。刪除後回首頁。

### 7.4 編輯紀錄（抽屜）

- 標題顯示項目 emoji 和名稱。
- 時間：`<input type="datetime-local">`，精確到分鐘；不可選未來時間（儲存時檢查）。
- 備註：多行文字。
- 底部：「刪除這筆」（紅，要確認）和「儲存」。

### 7.5 補其他日期（抽屜）

- 一個月曆，可以左右換月；點日期可多選，選中的變綠；已經有紀錄的日子下面有小點；未來的日期不能選。
- 下方一個時間欄位，預設 12:00，套用到選的每一天。
- 「加入 N 天」按鈕，N 隨選取數量更新，0 時不可按。加入後回到細節頁並以底部提示顯示「已加入 N 筆」（此提示沒有復原）。

### 7.6 設定 `#/settings`

- 備份：顯示上次備份時間（或「尚未備份」）；「匯出備份」直接下載「上次備份-YYYY-MM-DD.json」；「分享備份」用 Web Share API 傳檔（不支援時隱藏）；「匯入備份」用 `<input type="file" accept=".json,application/json">`。
- 匯入選檔後開「匯入確認」抽屜（§7.7）。
- 外觀：主題「跟隨系統 / 淺 / 深」。
- 記錄時震動：開關（裝置不支援震動時仍顯示，但無效）。
- 封存的項目：列表，每列有「取消封存」。
- 清除全部資料：紅字，要確認（確認文字提醒先備份）。清除後回首頁並重置所有設定（主題和震動除外）。
- 關於：版本號（從 package.json 注入）、項目數、紀錄數、一句「沒有帳號、沒有伺服器，資料不會離開這支手機」、資料存在瀏覽器裡、清除網站資料會遺失的提醒。

### 7.7 匯入確認（抽屜）

- 顯示摘要：匯出日期、幾個項目、幾筆紀錄。
- 兩顆按鈕「合併到現有資料」「覆蓋現有資料」；覆蓋要再確認一次。
- 檔案不合法（§8）時不開抽屜，直接顯示錯誤提示「不是『上次』的備份檔」。
- 完成後顯示「已匯入 N 個項目、M 筆紀錄」。

### 7.8 底部提示（toast）

- 單一元件，一次只顯示一條；黑底白字；可帶 0 到 2 顆按鈕；預設 8 秒後消失（純訊息型 3 秒）。
- 復原提示是它的一種用法。

## 8. 備份檔格式

UTF-8 JSON。

```json
{
  "app": "lasttime",
  "version": 1,
  "exportedAt": "2026-10-05T09:30:00.000Z",
  "items": [
    {
      "id": "muu6aqvrnk6ye",
      "name": "換瓦斯",
      "emoji": "🔥",
      "expectDays": 45,
      "archived": false,
      "created": 1791139600000
    }
  ],
  "records": [
    {
      "id": "muu6aqvsb9u86",
      "itemId": "muu6aqvrnk6ye",
      "ts": 1791139620000,
      "note": ""
    }
  ],
  "settings": { "theme": "system", "vibrate": true }
}
```

解析規則：

- `app` 不是 `"lasttime"` 或 `items` 不是陣列，就拒絕。
- `records` 缺少時視為空陣列。
- id 是任意非空字串。`ts`、`created` 必須是有限數字；不合格的單筆跳過，不整份拒絕。`expectDays` 可能是 null 或缺少。不認識的鍵忽略。
- `records` 裡 `itemId` 找不到對應項目（檔案內或現有資料內都沒有）的紀錄跳過。
- `settings` 只參考 `theme`（system / light / dark）和 `vibrate`，其他鍵忽略。**只有「覆蓋」時套用**；「合併」時保留現有設定。
- 合併：同 id 的項目、紀錄已存在就跳過，不覆蓋；新的加進來。
- 覆蓋：先清空兩張表，再寫入。
- 匯出完成後把 `lastBackupAt` 記為現在；匯入不改 `lastBackupAt`。

## 9. 離線、安裝、更新

- Manifest：名稱「上次」、`display: standalone`、`start_url: ./`、主題色與背景色、icon 192 / 512（含 maskable）、一個固定捷徑「新增項目」指向 `./#/?focus=1`（首頁開啟後聚焦輸入框）。
- Service Worker 預先快取全部打包資源（含字型），導覽請求離線時回應 `index.html`。
- 更新策略：新版 Service Worker 下載完成後**不立即接管**，等下次開啟（所有分頁關閉後）才切換，避免使用中突然重整。
- 不註冊任何推播或背景同步。

## 10. 非功能需求

| 面向 | 要求 |
| --- | --- |
| 離線 | 安裝後飛航模式下所有功能正常；程式碼中沒有任何對外的 fetch |
| 效能 | 冷啟動到首頁可操作 1 秒內（中階 Android）；100 個項目、3000 筆紀錄的清單捲動不掉幀 |
| 深色模式 | 跟隨系統，可手動切換；兩種模式都檢查對比，紅與綠在深色底可辨 |

## 11. 明確不做的事

- 推播或任何通知
- 帳號、登入、雲端同步、跨裝置
- 廣告、內購、評分邀請
- 任何分析、追蹤、錯誤回報 SDK
- 目標、連續天數、成就、徽章、進度百分比
- 社群分享、匯出成圖片
- 照片、影片
- 分類
- 日曆分頁（月視圖、年視圖熱度圖）
- 報告／統計分頁
- 匯入其他 app 的資料

項目數少（個位數到十幾個）時，以上都沒有用處。若將來需要，另開規格並把備份格式的 `version` 升為 2。

## 12. 測試策略

- **單元測試（Vitest）**：`calc.ts`（日曆日差含跨午夜與跨時區案例、字級與字重、到期、7 天統計、平均間隔、空缺）、`emoji.ts`（每條規則、順序陷阱如「洗車」「吃藥」）、`backup.ts`（合法檔、拒絕條件、缺欄位、壞紀錄跳過、合併去重、覆蓋）、`ids.ts`（長度與字元集）。
- **資料層測試**：用 `fake-indexeddb` 測 `db.ts` 的 CRUD 與刪項目連帶刪紀錄。
- **手動驗收**：§13 清單在 Android Chrome 上逐項試。
- CI 在部署前跑全部測試，失敗就不部署。
