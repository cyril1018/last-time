# 「上次」英文介面與推廣 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓「上次」有中英兩種介面（自動跟手機語言、設定可切換），自動配 emoji 認得英文名稱，編輯項目可展開「更多 emoji」，並補上搜尋與分享用的雙語描述。

**Architecture:** 自己寫的型別安全翻譯表（`src/lib/i18n/`），中文表是型別來源，英文表必須符合同一型別。目前語言由 `store.settings.language` 與 `navigator.languages` 算出，放在一個 Svelte 5 class 的 `$derived` 裡。`lib` 裡的純函式改收語言參數，不讀全域狀態；元件與 `log-flow.ts` 直接讀 `i18n`。

**Tech Stack:** Svelte 5（runes）、TypeScript strict、Vite 7、vite-plugin-pwa、Vitest + happy-dom、Dexie。

**Spec:** `docs/superpowers/specs/2026-10-14-i18n-english-design.md`

**與規格的命名對應：** 規格 §3.3 的 `errorMessage` 就是既有的 `saveErrorMessage`；規格 §2.2 的 `dateLocale(locale, languages)` 在程式裡叫 `dateLocaleFor`，以免和 `i18n.dateLocale` 屬性撞名。規格 §8.2 的寫死中文掃描範圍擴大為整個 `src/`（含 `main.ts`、`App.svelte`）。

## Global Constraints

- 只有兩種語言：`'zh-TW'` 與 `'en'`。設定值 `'system' | 'zh-TW' | 'en'`，預設 `'system'`。
- `languages[0]` 不分大小寫以 `zh` 開頭 → 中文；其他（含空陣列）→ 英文。
- 中文介面的每個字串、日期格式都必須與改版前一字不差（唯二例外：「洗」配 🧼、編輯畫面多一格「⋯」）。
- 不新增任何 npm 依賴。
- 純函式的語言參數一律必填，不給預設值。
- 只用 Unicode 13.0 以前的 emoji。
- 備份格式不變，`version` 維持 1；語言設定不進備份；「清除全部資料」保留 `theme`、`vibrate`、`language`。
- `<title>` 固定為 `上次 Last Time — 記下上次做某件事過了幾天`，執行期不改。
- 每個任務結束前 `npm test`、`npm run check` 都要通過；動到建置設定的任務另外跑 `npm run build`。
- Commit：用 repo 內已設定的 `Ted <38046383+cyril1018@users.noreply.github.com>`（不要改 git config）；訊息不加 `Co-Authored-By` 或任何 AI／模型名稱；不 push。
- 測試環境時區固定為 `Asia/Taipei`（`tests/setup.ts`）。
- **測試不得依賴執行機器的語言**：這台開發機的 node `navigator.languages` 是 `['zh-TW']`，GitHub Actions 是英文。任何會經過 `i18n` 的測試都要明確設定 `i18n.languages = [...]` 或 mock 的 `store.settings.language`。

## Review Focus

1. 英文星期標題 `M T W T F S S` 有重複字母，`MonthCalendar` 的 `{#each}` 若以字串為 key 會在英文介面直接拋錯 → 改用索引為 key，Task 5 有英文掛載測試。
2. `navigator.languages` 含有 `Intl` 不接受的標籤（例如 `en-US-x-` 這種壞值）→ `dateLocaleFor` 退回 `'en-US'`，不能讓整個畫面因 `RangeError` 掛掉。Task 1 有測試。
3. 舊 WebView 或 node 環境沒有 `navigator.languages`（`undefined`）→ 英文、不拋錯。Task 2 有測試。
4. 英文名稱大小寫、標點混用（`CAR-WASH`、`Dentist!`、`Mom's call`）→ 照樣配到正確 emoji。Task 7 有測試。
5. 語言設為 English 後「匯入備份 → 覆蓋」或「清除全部資料」→ 語言維持 English。Task 1、Task 3 有測試。

```ts
import type { LanguageSetting, Locale } from '../types'

/** `<html lang>` per locale. index.html's boot script spells the same two values out. */
export const HTML_LANG: Record<Locale, string> = { 'zh-TW': 'zh-Hant-TW', en: 'en' }

/** Manifest file per locale, relative to `base`. vite.config.ts emits both. */
export const MANIFEST_FILE: Record<Locale, string> = { 'zh-TW': 'manifest.webmanifest', en: 'manifest-en.webmanifest' }

/** Spec §2.2. Every Chinese variant gets Traditional Chinese; everything else gets English. */
export function resolveLocale(setting: LanguageSetting, languages: readonly string[]): Locale {
  if (setting !== 'system') return setting
  return /^zh/i.test(languages[0] ?? '') ? 'zh-TW' : 'en'
}

function intlAccepts(tag: string): boolean {
  try {
    return Intl.DateTimeFormat.supportedLocalesOf([tag]).length > 0
  } catch {
    return false
  }
}

/** The tag dates are formatted with: the phone's first English variant, so en-GB keeps its 24-hour clock. */
export function dateLocaleFor(locale: Locale, languages: readonly string[]): string {
  if (locale === 'zh-TW') return 'zh-TW'
  return languages.find((l) => /^en(-|$)/i.test(l) && intlAccepts(l)) ?? 'en-US'
}

/** Keeps `<html lang>` and the manifest link in step with the locale. A missing link (dev, tests) is fine. */
export function applyLocaleToDocument(locale: Locale, doc: Document, base: string): void {
  doc.documentElement.lang = HTML_LANG[locale]
  doc.querySelector('link[rel="manifest"]')?.setAttribute('href', `${base}${MANIFEST_FILE[locale]}`)
}
```

```ts
import { store } from '../app-store'
import type { Locale } from '../types'
import { resolveLocale, dateLocaleFor } from './locale'
import { messagesFor, type Messages } from './messages'

/** `navigator.languages`, or [] where it is missing (old WebViews, node). */
export function readLanguages(nav: { languages?: readonly string[] } | undefined = globalThis.navigator): readonly string[] {
  return nav?.languages ? [...nav.languages] : []
}

class I18n {
  /** The phone's language list; kept current by start(). Tests assign it directly. */
  languages = $state.raw<readonly string[]>(readLanguages())
  readonly locale: Locale = $derived(resolveLocale(store.settings.language, this.languages))
  readonly dateLocale: string = $derived(dateLocaleFor(this.locale, this.languages))
  readonly t: Messages = $derived(messagesFor(this.locale))

  /** Follows system language changes while the app is open. Returns the cleanup. */
  start(): () => void {
    const update = () => { this.languages = readLanguages() }
    window.addEventListener('languagechange', update)
    return () => window.removeEventListener('languagechange', update)
  }
}

export const i18n = new I18n()
```

```ts
import type { Locale } from './types'
import { messagesFor } from './i18n/messages'

const WEEKDAYS = ['日', '一', '二', '三', '四', '五', '六'] as const
const pad = (n: number) => String(n).padStart(2, '0')
const isZh = (dateLocale: string) => /^zh/i.test(dateLocale)

/** Intl output with narrow/no-break spaces folded to plain spaces, so the text is the same on every ICU. */
function intl(ts: number, dateLocale: string, opts: Intl.DateTimeFormatOptions): string {
  return new Intl.DateTimeFormat(dateLocale, opts).format(new Date(ts)).replace(/[  ]/g, ' ')
}
const MONTH_DAY: Intl.DateTimeFormatOptions = { month: 'short', day: 'numeric' }
const CLOCK: Intl.DateTimeFormatOptions = { hour: 'numeric', minute: '2-digit' }

/** Fixed 24-hour HH:MM: what <input type="datetime-local"> needs. For display use formatClock. */
export function formatTime(ts: number): string {
  const d = new Date(ts)
  return `${pad(d.getHours())}:${pad(d.getMinutes())}`
}

export function formatClock(ts: number, dateLocale: string): string {
  return isZh(dateLocale) ? formatTime(ts) : intl(ts, dateLocale, CLOCK)
}

export function formatMonthDay(ts: number, dateLocale: string): string {
  if (!isZh(dateLocale)) return intl(ts, dateLocale, MONTH_DAY)
  const d = new Date(ts)
  return `${d.getMonth() + 1}月${d.getDate()}日`
}

export function formatShort(ts: number, dateLocale: string): string {
  if (!isZh(dateLocale)) return intl(ts, dateLocale, { ...MONTH_DAY, ...CLOCK })
  return `${formatMonthDay(ts, dateLocale)} ${formatTime(ts)}`
}

export function formatLong(ts: number, dateLocale: string): string {
  if (!isZh(dateLocale)) return intl(ts, dateLocale, { weekday: 'short', year: 'numeric', ...MONTH_DAY, ...CLOCK })
  const d = new Date(ts)
  return `${d.getFullYear()}年${d.getMonth() + 1}月${d.getDate()}日 週${WEEKDAYS[d.getDay()]} ${formatTime(ts)}`
}
```

```ts
import { DuplicateNameError, EmptyNameError, FutureTimeError, InvalidTimeError } from './store.svelte'
import type { Locale } from './types'
import { messagesFor } from './i18n/messages'

/** The toast for a failed store write. Errors a given call cannot throw simply never match. */
export function saveErrorMessage(e: unknown, locale: Locale): string {
  const m = messagesFor(locale)
  if (e instanceof EmptyNameError) return m.errors.emptyName
  if (e instanceof DuplicateNameError) return m.errors.duplicateName
  if (e instanceof FutureTimeError) return m.errors.futureTime
  // Defensive: the UI only builds finite timestamps, but the store rejects anything else.
  if (e instanceof InvalidTimeError) return m.errors.invalidTime
  return m.common.saveFailed
}
```
